# RLM1 — RL на минутках BTCUSDT / ETHUSDT (протокол, зафиксирован до запуска)

Постановку задал пользователь через координатора. Аналог прогона координатора на золоте.

**Данные.** Спот Binance, 1m (`data_m1.py`). Сетка минут непрерывная, пропуски — ffill (r = 0).

**Решение и позиция.** Каждую минуту позиция ∈ {−1, 0, +1}. Горизонт удержания свободный.

**Награда (обучение).** pos_t · (r_{t+1} − r̄_train) − cost · |Δpos| − pen_t.
- r — лог-доходность следующей минуты.
- r̄_train — средняя минутная доходность на окне обучения. Её вычитание не даёт агенту выучить направление рынка.
- Издержки cost ∈ {5 bp (тейкер), 2 bp (мейкер)} на единицу изменения позиции.
- Штраф pen задаётся вариантом:
  - **А** — без штрафа (pen = 0);
  - **Б** — штраф за время вне рынка: pen = 1e-7 · (exp(min(flat_min / 1440, 6)) − 1) за каждую минуту без позиции. Это ≈ 1 bp за первые сутки, ≈ 6 bp за вторые.
- Штраф есть только в обучении. В оценке — реальная доходность (без вычета среднего) минус издержки.
- **Фандинг не учитывается.** На минутных сделках он мал, но у долгих удержаний он есть: это оговорка.

**Наблюдение (259 чисел).**
- Последние 240 значений z = r / σ₁₄₄₀, клип ±8.
- Доходности за 15/60/240/1440/4320/10080 минут в единицах σ₁₄₄₀·√n.
- ln(σ₆₀ / σ₁₄₄₀) и ln(σ₁₄₄₀ / σ₄₃₂₀₀) — вторая трактует «σ₁₄₄₀ скользящая / σ₁₄₄₀» как текущий режим против 30-дневного.
- Положение цены в диапазоне суток и недели (×2 − 1).
- Час суток и день недели (sin, cos).
- Состояние: one-hot позиции, log1p(минут в позиции) / 5, плавающий PnL позиции в единицах σ₁₄₄₀·√(минут в позиции).
- Контекстные признаки стандартизуются средним и σ окна обучения.

**Модель.** PPO из stable-baselines3:
- MLP [32, 32], gamma 0.999, gae_lambda 0.98, ent_coef 0.01, lr 2e-4;
- n_steps 2048, batch 4096, 8 сред (векторная среда на numpy);
- эпизод — неделя (10080 мин) со случайным стартом в окне обучения;
- 6 млн шагов, CPU.

**Отрезки.**
- Обучение: 2019-01-01 … 2022-12-31.
- Валидация: 2023. Оценка после каждой четверти обучения (1.5 / 3 / 4.5 / 6 млн шагов), выбор чекпоинта — по Sharpe 2023.
- Тест: 2024-01-01 … последний полный день, один прогон выбранного чекпоинта.
- Оценка ведётся детерминированной политикой (argmax). Период режется на недельные отрезки, их прогон идёт батчем. Каждый отрезок начинается без позиции, в конце недели позиция закрывается с издержками.

**Конфигурации.** 3 сида × {BTC, ETH} × {А, Б} × cost {5, 2} = 24 прогона. Сначала cost 5 (12 прогонов), затем cost 2.

**Отчёт** по каждому прогону и среднее по сидам:
- доходность по годам, Sharpe (по дневным суммам, √365), max DD;
- бета к купить-и-держать монеты (регрессия дневных доходностей) и альфа-Sharpe — Sharpe остатка α + ε;
- сделок в день (изменений позиции), доля времени в рынке, медиана удержания (мин).

**Успех.** Конфигурация считается успешной, если на тесте 2024–26 выполнено всё сразу:
- средний по сидам альфа-Sharpe > 0.5;
- альфа-Sharpe > 0 у ≥ 2 из 3 сидов;
- средний Sharpe > 0.

Иначе — провал.

**Счёт вариантов.** 8 конфигураций (× 3 сида).

## Дополнение (до запуска): вариант C и метрика связи с трендом

**Вариант C — контроль «может ли RL переоткрыть дневной тренд».**
- В наблюдение добавлены (ln c_d − ln SMA_n) / (σ_d·√n) для n = 20, 50, 100 дней и доходности за 20/60/120 дней в σ_d·√n.
- c_d — дневные закрытия по минуткам, σ_d — 20-дневная σ дневных доходностей. Берутся только завершённые дни: значение для дня D рассчитано по закрытиям до D−1.
- gamma 0.99999, gae_lambda 0.995, без штрафа, cost 5 bp. Остальное как в A.
- Прогонов: 3 сида × {BTC, ETH}.

**Метрика для всех вариантов** (валидация и тест): корреляция средней дневной позиции агента с позицией `trend.py` (книга BTC+ETH, 20% vol, позиция дня D) — по знаку и по размеру.

**Вывод по C.** RL «видит» тренд, если средний Sharpe на тесте ≥ 0.7 и корреляция со знаком тренда > 0.5. Если тренд не видит ни A, ни B, ни C, вывод «на минутках ничего нет» ограничен методом.

**Порядок.** Сначала cost 5 для A, B, C (18 прогонов), затем cost 2 для A, B (12).

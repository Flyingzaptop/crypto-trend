# PNL1 — сеть оптимизирует P&L напрямую, без RL (протокол, зафиксирован до запуска)

**Вопрос.** Может ли небольшая сеть, обученная на дифференцируемом критерии прибыли (Sharpe, mean−variance, mean−drawdown), найти устойчивую позицию на BTC, ETH и золоте, которая лучше купить-и-держать и тренда?

## Рынки и бары

| рынок | бары | данные | издержки | фандинг |
|---|---|---|---|---|
| BTCUSDT, ETHUSDT | 1d, 4h | спот Binance REST (кэш `data/ml`) | 10 bp на единицу \|Δp\| | в оценке: дневной фандинг перпа, для 4h — /6 на бар |
| XAUUSD | H1, H4, D1 | M1 из Google Drive → бары `resample(...).last().dropna()` | 1 bp | нет |

У золота только реальные бары: выходные и паузы рынка — это одна доходность через разрыв.

## Модель позиции
- Решение на закрытии бара t: p_t = tanh(f(x_t, p_{t−1}, h_{t−1})) ∈ [−1, 1].
- P&L бара: p_t · (r_{t+1} − r̄_train) − c · |p_t − p_{t−1}|.
  - На обучении дрейф r̄_train вычтен, r нормированы на σ_train.
  - В оценке — сырые r, издержки и фандинг.
- **Позиция p_{t−1} — вход сети, рекуррентно для обеих архитектур.** Сеть разворачивается по времени через кусок (без teacher forcing): MLP получает [x_t, p_{t−1}] на каждом шаге, GRU — то же как вход ячейки плюс своё скрытое состояние. Градиент проходит через всю цепочку позиций. Так оборот и издержки учитываются честно.
- **Обучение** на непрерывных кусках по 256 баров со случайным началом, 64 куска в батче. Позиция и скрытое состояние в начале куска — 0.
- **Оценка** — один непрерывный проход по периоду, старт без позиции.

## Признаки (на закрытии t, только прошлое; стандартизация средним/σ обучения)
- σ — скользящая σ 1-бар доходностей за 100 баров.
- Доходности за n ∈ {1, 2, 4, 8, 16, 32, 64, 120} баров в единицах σ·√n.
- Расстояние до SMA n ∈ {20, 50, 100, 200}: (ln c − ln SMA_n) / (σ·√n).
- ln(σ_20/σ_100) и ln(σ_100/σ_500).
- Положение в диапазоне 20 и 100 баров (×2 − 1).
- Время: день недели sin/cos; для внутридневных баров ещё час суток sin/cos.

## Лоссы (4)
Все считаются на куске и усредняются по батчу; доходности нормированы на σ_train.
- **L1**: −mean / std P&L (Sharpe куска).
- **L2a**: −mean + 1·var.
- **L2b**: −mean + 5·var.
- **L3**: −mean + 1·MDD/L, где MDD — максимальная просадка накопленного P&L куска, L = 256.

## Модели (4)
- MLP: 2 слоя ширины {16, 64}.
- GRU: 1 слой {16, 64} + линейный выход.
- Общие настройки: dropout 0.2 на входе скрытого слоя, AdamW (lr 1e-3, weight_decay 1e-3).
- До 150 эпох (эпоха = 50 батчей). Ранняя остановка по Sharpe валидации (сырые r, издержки, фандинг): терпение 15 эпох, берётся лучшая эпоха.

Итого на рынок × бар 16 точек × 3 сида.

## Отрезки
- Обучение — с начала данных (крипта 2017-08, золото 2016-09) по 2022-12-31.
- Валидация 2023: ранняя остановка и **выбор точки** (лосс × модель) — по средней по сидам Sharpe валидации, отдельно для каждого из 7 рынков × баров.
- **Тест 2024-01 … последний бар — один раз, только для выбранной точки:** 3 сида и ансамбль (средняя позиция).
- **Walk-forward** для выбранной конфигурации: годы 2019…2026. Модель для года Y обучена на данных < Y−1, ранняя остановка по году Y−1, прогноз на год Y; 3 сида.

## Контроли
- **Альфа.** Альфа-Sharpe сверх купить-и-держать и сверх тренда: регрессия дневного P&L одновременно на дневную доходность купить-и-держать и тренда. Тренд для крипты — `trend.py` на одной монете (дневки, 20% vol); для золота — то же правило SMA 20/50/100 на дневках золота.
- **Плацебо.** Доходности бара перемешаны блоками по 20 баров (по всей истории). Из них собирается цена, по ней пересчитываются признаки и цели. Выбранная конфигурация обучается и оценивается так же; ожидание — Sharpe ≈ 0.
- **Разброс** по 3 сидам; оборот за год; время в рынке (|p| > 0.05); средняя |p|.
- **Дефлированный Sharpe** выбранных точек: N = 7 × 16 = 112 испытаний, дисперсия Sharpe испытаний — по Sharpe валидации всех точек.

## Успех (для рынка × бара)
На тесте одновременно:
- средний по сидам Sharpe > Sharpe купить-и-держать;
- альфа-Sharpe сверх купить-и-держать и тренда > 0.5;
- ≥ 2 из 3 сидов с альфой > 0;
- плацебо: Sharpe теста |SR| < 0.5;
- walk-forward: средний Sharpe 2019–2026 > 0.

## Дополнение 1 до запуска: M1 — основной эксперимент

По требованию пользователя основной эксперимент — **решение каждую минуту** (как в RLM1). Бар-версия выше (1d/4h/H1) идёт как дешёвый бейзлайн на CPU параллельно, её критерии те же.

**Код:** `pnl_m1.py`.

**Позиция.** p_t = tanh(…) каждую минуту.
- P&L минуты: p_t·(r_{t+1} − r̄_train) − c·|p_t − p_{t−1}|. На обучении r нормированы на σ_train минуты.
- В оценке — сырые r. Фандинг не учитывается (оговорка, как в RLM1).
- Других ограничений частоты нет: держать позицию заставляют только издержки.

**Вход.**
- Окно последних 240 минут z = r/σ₁₄₄₀.
- Контекст RLM1: доходности 15…10080 мин в σ·√n, ln σ₆₀/σ₁₄₄₀, ln σ₁₄₄₀/σ₄₃₂₀₀, положение в диапазоне суток и недели, час суток и день недели.
- Дневной контекст варианта C: (ln c − ln SMA_n)/(σ_d√n) для n = 20, 50, 100 дней и доходности 20/60/120 дней в σ_d√n — только по завершённым дням.
- p_{t−1}.
- Признаки — те же, что в `rlm1.prep`, стандартизованы по обучению.

**Архитектура.**
- Энкодер считает e_t для всех минут куска параллельно:
  - MLP 2 слоя ширины {16, 64} на [окно, контекст];
  - 1D-CNN по окну (1→8 каналов, ядро 8, шаг 4; 8→8, ядро 4, шаг 2) + линейный слой 32 на [свёртка, контекст];
  - GRU 1 слой {16, 64} по минутам на [z_t, контекст_t], с прогревом 240 минут перед куском.
- Рекуррентная голова позиции: p_t = tanh(v·tanh(A·e_t + b·p_{t−1} + c) + d), скрытый размер 16. Разворачивается по куску циклом по времени, параллельно по кускам; градиент проходит через всю цепочку позиций.
- Dropout 0.2, AdamW (lr 1e-3, wd 1e-3), clip 1.0.

**Обучение и оценка.**
- Куски по 2880 минут (2 дня), батч 128 кусков, эпоха = 20 батчей, до 60 эпох.
- Ранняя остановка по Sharpe валидации 2023, терпение 8.
- Оценка — недельные куски батчем, старт без позиции, закрытие в конце недели с издержками.

**Лоссы** L1, L2a, L2b, L3 — как выше, на кусках минут.

**Рынки и издержки:** BTCUSDT 5 и 2 bp, ETHUSDT 5 и 2 bp, XAUUSD 1 bp. Обучение: крипта 2019–2022, золото 2017–2022. Валидация 2023. Тест 2024-01…последний день — один раз, только для выбранной точки.

**Сетка.** 4 лосса × 5 моделей × 5 рынков/издержек × 3 сида = 300 прогонов.
- Если бюджет GPU Colab не вместит всю сетку, прогоны идут в таком порядке, и урезание фиксируется в `STATUS.md` до запуска:
  1. cost 5 bp (BTC, ETH) и золото;
  2. затем cost 2 bp.
- Внутри порядок моделей: MLP 64 → GRU 64 → CNN → MLP 16 → GRU 16.

**Выбор, контроли, критерии** — как в основном протоколе:
- выбор по средней по сидам Sharpe валидации 2023, отдельно для каждого рынка × издержек;
- тест один раз;
- walk-forward 2020–2026 для выбранной (крипта: годы после первого года обучения);
- плацебо (доходности перемешаны блоками по 20 минут);
- альфа сверх купить-и-держать и тренда;
- 3 сида;
- дополнительные метрики: сделок в день (смен знака позиции при |p| > 0.05), медиана удержания, время в рынке, корреляция средней дневной позиции с позицией `trend.py`.

**Вычисления.** Colab GPU через CLI. Весь прогон внутри ядра одним `colab exec`, сессия закрывается сразу по окончании. Перед свипом — замер скорости, ETA и расход CU в `STATUS.md`. На балансе ≈ 8.4 CU, поэтому берётся самый дешёвый подходящий GPU (L4/T4): модели маленькие.

## Дополнение 4 (07:20 UTC): провал оптимизации M1, правки до продолжения

**Наблюдение по первым прогонам M1.** Sharpe на обучении отрицательный: BTC 5 bp −5.8, −77.7, −8.0. У MLP64/L2a −78 при времени в рынке 0: позиция |p| < 0.05 дрожит каждую минуту и платит издержки. Сеть не выучила даже тривиальное p ≡ 0, которое дало бы 0. Это провал оптимизации. Свип остановлен, готовые прогоны (сетка дополнения 3) отчитываются как «до правок».

**Правки** (для всех дальнейших M1-прогонов):
- **(а)** Выходной слой головы позиции инициализирован нулями: старт с p ≡ 0.
- **(б)** Мёртвая зона: p_eff = sign(p) · max(|p| − 0.1, 0) / 0.9. Это позиция для P&L, издержек и рекуррентного входа. Мелкие колебания не торгуются.
- **(в)** Куски по 720 минут: короче цепочка для градиента, truncated BPTT на длину куска. Батч 512 кусков, эпоха = 100 батчей, до 40 эпох. Ранняя остановка разрешена только после 3000 градиентных шагов (30 эпох), терпение 8 эпох.
- **(г)** lr 3e-4.
- **Логирование:** train-лосс (среднее по эпохе) и Sharpe валидации по эпохам. Санити: лосс для p ≡ 0 равен 0 по построению, с ним сравнивается кривая.

**Порядок.** Сначала одна конфигурация — GRU64, L1, BTC 5 bp, сид 0. Её кривые обучения и валидации показываются координатору до запуска остальной сетки. Остальная сетка (дополнение 3) — только после этого.
- **Уточнение (б) до запуска.** При нулевой инициализации q = 0 лежит внутри мёртвой зоны. Там производная зоны равна 0, градиент не проходит, и сеть навсегда осталась бы на p ≡ 0. Поэтому зона применяется со straight-through градиентом: прямой проход — p_eff, обратный — как для q.

## Дополнение 5 (08:05 UTC): правило остановки M1-ветки, записано до просмотра кривых контрольного прогона

Контрольный прогон: GRU64, L1, BTC 5 bp, сид 0, с правками дополнения 4 (нулевая инициализация, мёртвая зона со straight-through, куски 720 мин, батч 512, эпоха = 100 батчей, lr 3e-4). Остальная M1-сетка не запускается.

**Правило.** Если после ≥ 3000 градиентных шагов (30 эпох) выполняется хотя бы одно из условий:
- train-лосс не опустился заметно ниже 0 (лосс при p ≡ 0 равен 0 по построению);
- train Sharpe ≤ 0,

то M1-ветка PNL1 останавливается, остальная сетка не запускается. В `RESULTS_PNL1.md` M1 записывается как «провал оптимизации» вместе с кривыми. Если условие не выполнено, кривые показываются координатору, решение про остальную сетку принимает он.

**Что пишется по эпохам:** train-лосс, train Sharpe, Sharpe на валидации 2023, сделок в день, время в рынке.

**Семь прогонов M1 сетки дополнения 3** (BTC 5 bp) сделаны до правок дополнения 4. В выборе не участвуют, отчитываются отдельно как «до правок».

**Бар-бейзлайн** (1d/4h/H1): Sharpe на валидации — оценка завышена, потому что берётся лучшая эпоха и лучшая из 16 точек на одних данных 2023. Находкой он не называется. Решающее — тест 2024–26, плацебо, walk-forward, альфа-Sharpe > 0.5 сверх купить-и-держать и тренда и дефлированный Sharpe.
